# v0.3.6

## What's new

- **New performance overlay styles** (Insert menu → Overlay): compact, strip, graph and histogram, telemetry and mini, beside the earlier card. Square panels in the launcher's colours, frames coloured against the frame rate limit (60 without one), 1% and 0.1% lows and percentiles over the last 2048 frames. The overlay goes in any corner or the centre of the top or bottom edge, at a chosen distance from the edges, at 50-300% size; the menu shows it live as you change it. The telemetry style also shows the busiest threads, GPU memory tracking faults and pipelines made per second.
- **Fixed: renderer v3 took a minute or more to start** (since v0.3.5). The parallel shader compiling meant for the first start ran at every start: the cached compute pipelines were built again each time. Now it is used only while preparing the shaders the first time; a normal start shows the first frames in about 15 seconds again.
- **Fixes from the iss_pc core** (HayatoG and contributors):
  - a freeze when the game waits on a lock it does not hold ([iss_pc #637](https://github.com/HayatoG/iss_pc/pull/637));
  - a Windows freeze inside the GPU page fault handler with precise readbacks ([iss_pc #638](https://github.com/HayatoG/iss_pc/pull/638));
  - a hang right after the first-start shader preparation ([iss_pc #625](https://github.com/HayatoG/iss_pc/pull/625));
  - controller vibration sent at most 10 times a second (a crash on SteamOS handhelds, [iss_pc #505](https://github.com/HayatoG/iss_pc/issues/505));
  - renderer v2 uses video memory more carefully: an automatic budget for its textures and less thrashing when the card is full.
- **Linux / Steam Deck: the launcher's update check works on SteamOS and Fedora.** The package looked for the system's certificates in Ubuntu's place, so the check failed with "could not reach GitHub".

# v0.3.6

## Что нового

- **Новые стили оверлея производительности** (меню Insert → Оверлей): компактный, лента, график и гистограмма, телеметрия и мини — рядом с прежней карточкой. Квадратные панели в цветах лаунчера, кадры окрашены относительно лимита FPS (без лимита — 60), 1% и 0.1% и процентили считаются по последним 2048 кадрам. Оверлей ставится в любой угол или по центру сверху и снизу, с выбранным отступом от краёв, размером 50–300%; меню показывает его вживую, пока вы его настраиваете. Стиль «Телеметрия» показывает ещё самые загруженные потоки, ошибки памяти GPU и создание конвейеров в секунду.
- **Исправлено: рендер v3 запускался минуту и дольше** (с версии v0.3.5). Параллельная сборка шейдеров, нужная для первого запуска, работала при каждом запуске: вычислительные конвейеры из кэша каждый раз собирались заново. Теперь она используется только при подготовке шейдеров в первый раз; обычный запуск снова показывает первые кадры примерно через 15 секунд.
- **Исправления из ядра iss_pc** (HayatoG и участники):
  - зависание, когда игра ждёт на блокировке, которой не владеет ([iss_pc #637](https://github.com/HayatoG/iss_pc/pull/637));
  - зависание в Windows внутри обработчика страничных ошибок GPU при точной выгрузке ([iss_pc #638](https://github.com/HayatoG/iss_pc/pull/638));
  - зависание сразу после подготовки шейдеров при первом запуске ([iss_pc #625](https://github.com/HayatoG/iss_pc/pull/625));
  - вибрация геймпада — не чаще 10 раз в секунду (вылет на портативных ПК с SteamOS, [iss_pc #505](https://github.com/HayatoG/iss_pc/issues/505));
  - рендер v2 аккуратнее расходует видеопамять: автоматический бюджет для текстур и меньше пробуксовки, когда видеокарта заполнена.
- **Linux / Steam Deck: проверка обновлений в лаунчере работает в SteamOS и Fedora.** Пакет искал системные сертификаты там, где они лежат в Ubuntu, и проверка завершалась ошибкой «не удалось связаться с GitHub».
